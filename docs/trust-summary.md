# 信任摘要 · 设计草案（尚未实现）

> 状态：**设计文档 / 未实现**。本文件只描述最小可验证版本，不改代码。
> 现有四能力位、敏感名单、JSONL 审计的判定逻辑一行不改；这里只加一层**只读聚合**。

## 1 · 一句话

现在你必须翻 JSONL 才能知道「这个根到底放开了多大」。目标是把这件事变成面板上的一句话：

> 该根有写权限但**无**删权限；`.env` 已被敏感名单拦截；过去 7 天写入 3 次，均来自同一会话。

## 2 · 为什么需要它（不是加功能，是换叙事）

「细粒度权限」听起来像**更多配置**，用户第一反应是「更麻烦」。
「信任的可见证据」听起来像**更少的疑问**：配置一次，之后每次都能用一句话验证自己配得合不合理。

同一套代码，两种叙事。差别不在能力，在**用户拿到手的第一个反馈是什么**。
现在第一个反馈是一行 JSONL；改成一句人话。

## 3 · 三个使用场景

**场景 A · 第一次开附加根后的自我怀疑**
你刚给 `D:\work\proj-a` 开了 `write`。面板立刻显示：`可写 · 不可删 · 敏感文件已拦 5 类 · 暂无写入`。你一眼确认「够用，没多给」。

**场景 B · 三个月后审计**
有人问「这个目录 Agent 到底改过什么」。打开面板：`过去 7 天写入 3 次，均来自会话 a1b2；最近一次 11-20 15:04；0 次被拒`。不需要 `grep` JSONL。

**场景 C · 被拒时看懂原因**
Agent 说「写不进去」。面板那一行直接写 `最近拒绝：敏感名单（.env）· 11-20 14:52`，而不是让你去猜是路径越界还是能力位不够。

## 4 · 最小可行版本

### 4.1 触发时机（三处，都不改变判定）

| 时机 | 做什么 | 开销 |
|---|---|---|
| 打开面板（「根 N」胶囊） | 计算并渲染全部根的摘要 | 一次聚合，通常 < 60ms |
| `workspace_roots action=status` | 返回同样的摘要字段（给 CLI / 模型读） | 同上，走缓存 |
| 写入判定之后（异步） | 只失效缓存，不在请求路径上做聚合 | 一次 `cache.delete(root)` |

**不在** `resolve()` 里做任何聚合 —— 判定必须保持纯函数、同步、可单测。

### 4.2 摘要字段（每个根一行）

```json
{
  "root": "D:\\work\\proj-a",
  "caps": ["read", "write"],
  "verdict": "可写 · 不可删",
  "sensitiveHit7d": 1,
  "writes7d": 3,
  "sessions7d": 1,
  "denied7d": 0,
  "lastWrite": 1763600000000,
  "window": "7d",
  "empty": false
}
```

渲染成一句话的规则（优先级从高到低，只取前 3 个分句，避免长句）：

1. `caps` → `可写 · 不可删` / `只读` / `可读可写可删`
2. `sensitiveHit7d > 0` → `敏感名单已拦 N 次（最近：.env）`
3. `writes7d > 0` → `过去 7 天写入 N 次${sessions7d === 1 ? "，均来自同一会话" : `，来自 ${sessions7d} 个会话`}`
4. `denied7d > 0` → `最近拒绝：${reason}（${time}）`
5. `empty` → `暂无写入记录`

### 4.3 怎么聚合（从现有 JSONL）

现有审计行已经是判定结果（含 `decision`、`rule`、`root`、`tool`、`ts`）。聚合是纯读：

1. 取 `.dsh/multi-workspace-audit.jsonl` 与轮转出来的旧文件，**只读尾部 ≤ 5MB**（够覆盖 7 天；不够就标 `window: "partial"` 而不是假装完整）；
2. 逐行 `JSON.parse`，单行解析失败就跳过并计数（不中断，也不静默：`badLines` 进返回值）；
3. 按 `root` 分组累加 `writes7d` / `sessions7d` / `denied7d` / `sensitiveHit7d`；
4. 结果进内存缓存，键 = `(文件 mtime, size)`；命中就不重算。

**为什么是 5MB**：现有轮转阈值就是 5MB，聚合窗口与轮转单位对齐，不需要新的配置项。

### 4.4 性能开销（可测）

- 5MB JSONL ≈ 2–4 万行；Node 逐行 parse + 累加在普通机器上 **< 50ms**（单次）；
- 面板打开时 6 个根 × 一次聚合 = 一次文件读 + 一次遍历，不是 N 次；
- 缓存命中后 **< 1ms**；
- 验收门槛：5000 行 fixture 上聚合 < 30ms（进 `tests/`，不进实现）。

### 4.5 与四能力位 / 敏感名单的关系

| 关系 | 说明 |
|---|---|
| 只读，不改判定 | 摘要字段全部是「判定结果的统计」，没有任何一条写回规则 |
| `verdict` 是派生 | 由 `caps` 直接映射，不引入新的权限概念 |
| 敏感名单优先 | 摘要里单独列 `sensitiveHit7d`，因为它是**先于根匹配**的一道闸，含义与能力位不同 |
| 会话级临时根 | 摘要多一个 `expiresAt` 倒计时分句（`还有 42 分钟过期`），这是它最容易出事的地方 |
| `evaluate` | 复用同一份聚合：`evaluate` 回答「这次会不会过」，摘要回答「过去实际怎么过的」 |

### 4.6 风险与缓解

| 风险 | 缓解 |
|---|---|
| 摘要看起来像「保证」 | 文案里显式写窗口：`过去 7 天`、`窗口不完整`；不写「从未」。 |
| 路径泄密 | 摘要只显示根的开头与末段（`D:\work\...\proj-a`），完整路径只在展开后显示 |
| 聚合慢拖累面板 | 缓存 + 尾部读取 + 上限 5MB；超过就 `window: partial` |
| 轮转边界导致漏算 | `window` 字段标注是否完整；`badLines` 计数一并返回 |
| 用户误以为这是审计合规工具 | DETAIL.md 里明写「不是合规审计，是可读性层」 |

## 5 · 不做的事

- 不做跨机器导出报表；

- 不把摘要写进提示词（它给人看，不给模型看）。
